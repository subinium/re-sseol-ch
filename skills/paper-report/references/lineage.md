# 인용 계보 만들기

- 참고문헌(references): 이번 논문이 인용한 이전 논문. 전작, 비교 대상, 도구.
- 피인용(citations): 이번 논문을 인용한 이후 논문. 후속작, 반박, 응용.

## 1. 재료

`lineage.py`가 만드는 `lineage.md`에는 이런 것이 들어 있다.
- 참고문헌 목록과 인용 문맥 문장(이번 논문 본문에서 그 논문을 언급한 실제 문장)
- 인용 의도(background, methodology, result)와 영향력 플래그
- 후속작 목록, 저자 정보(h-index, 대표 논문, 소속)

API가 막혀 비었으면 `references.txt`와 본문 인용 위치를 직접 읽어 채운다.

데이터 품질 주의:
- 인용 문맥 속 `[8]` 같은 번호는 API가 파싱한 버전 기준이라 지금 PDF와 다를 수 있다. `text.txt`에서 같은 문장을 찾아 페이지로 적는다.
- Semantic Scholar 피인용 목록은 최근 인용부터 온다. 인용이 많은 논문은 표본일 뿐이므로 대표 후속작은 OpenAlex 피인용순이나 웹으로 찾는다.
- OpenAlex에는 제목·연도·저자가 잘못 병합된 레코드가 섞여 있다. 고른 논문은 원문 첫 페이지로 다시 확인한다.
- 피인용 수는 출처마다 몇 배씩 다르다. 레포트에는 한 출처만 쓰고 출처명과 날짜를 붙인다.

## 2. 전작 고르기 (3~6편)

서사에 필요한 순서로 고른다.
1. 방법론 절에 이름이 나오는 논문 ("We build on X", "Following X")
2. 결과 표의 비교 대상
3. 서론에서 문제 정의의 출처로 쓰인 논문
4. 영향력 플래그가 있고 인용 문맥이 여러 번인 논문
5. 분야의 시작점

같은 역할이 여럿이면 가장 이른 것과 가장 직접적인 것만 남긴다.

## 3. 관계 어휘 (이것만 쓴다)

| 관계 | 뜻 | 필요한 근거 |
|---|---|---|
| 확장 | 전작의 방법 위에 쌓음 | "we extend", "building on", "following" |
| 대체 | 전작의 핵심 부품을 빼고 다른 것으로 바꿈 | "instead of X", "without X" |
| 반박 | 전작의 주장이 틀렸거나 한정적이라고 보임 | "contrary to", "we find that X does not" |
| 비교 대상 | 결과 표에서 이긴/진 상대 | 결과 표의 행 |
| 도구로 사용 | 전작의 데이터셋, 모델, 측정법을 가져다 씀 | 실험 설정 절 |
| 동시기 경쟁 | 비슷한 시기 독립적으로 비슷한 것을 함 | "concurrent work" 또는 두 논문의 공개일 |
| 문제 제기 | 전작이 문제를 처음 정의하거나 관찰함 | 서론의 인용 문맥 |
| 예측 검증 | 전작(이론)이 예측한 것을 이번 논문이 관측·확인함 | "predicted by", "as predicted", 결과·논의 절의 비교 |
| 메커니즘 규명 | 전작이 관찰한 현상의 원인을 이번 논문이 밝힘 | 결과·논의 절에서 전작의 관찰을 설명하는 문장 |

- 근거 문장은 서론뿐 아니라 결과·논의 절에서도 찾는다. 생물·물리 논문은 "we extend" 같은 표현을 잘 안 쓰므로, 문장의 뜻으로 관계를 판단하고 원문을 원장에 그대로 옮긴다.
- "영감을 받음", "~ 덕분에 나옴" 같은 인과는 저자가 직접 그렇게 말했을 때만 쓴다.
- "처음", "최초", "원조"는 그 논문이 스스로 그렇게 말하거나, 관련 연구 절을 읽어 선행 연구가 없음을 확인했을 때만 쓴다. 전작의 관련 연구 절에는 대개 더 이른 연구가 나온다.
- 두 전작의 주장이 서로 엇갈리면 한쪽 편을 들지 말고 "된다 vs 안 된다"처럼 둘 다 보여준다. 좋은 이야깃거리다.

## 4. 후속작 고르기 (2~4편)

- 이번 논문을 방법론으로 인용한 것을 우선한다.
- 반박이나 한계 지적 논문이 있으면 하나 넣는다.
- 후속작이 이번 논문의 무엇을 가져갔는지는 후속작 본문의 문장으로 확인한다. 후속작이 중간 단계(다른 변형)를 거쳐 가져갔으면 그 단계도 적는다.

## 5. 저자 교차 비교

전작, 이번 논문, 후속작의 저자 목록을 한 표에 놓고 겹치는 이름을 찾는다. 감사의 글에 나오는 이름도 대조한다. 동일인 판단 근거는 `people-context.md`를 따른다.

## 6. 연대기 표

골라낸 논문을 연도순 표로 만든 뒤 파트로 옮긴다.

| 공개일 | 논문 (팀/기관) | 한 것 | 남은 문제 | 이번 논문과 관계 | 원장 |
|---|---|---|---|---|---|
| 2014-09 | ... | ... | ... | 문제 제기 | L1 |
| YYYY-MM | 이번 논문 | ... | ... | - | F1 |

- "남은 문제"가 다음 행의 동기가 되도록 배치한다.
- 날짜 기준(arXiv 최초 공개 또는 게재)을 하나로 정하고 원장에 적는다. 같은 해 논문은 월·일까지 비교해 순서를 확인한다.

## 7. 전작 확인

전작마다 원문 첫 페이지로 확인한다.
- 정확한 제목, 제1저자, 공개일, 발표처
- 당시 소속 (현재 소속이 아님)
- 전작이 실제로 한 것 (이번 논문의 요약만 믿지 않는다)

이번 논문이 전작을 다르게 요약했으면 전작 원문을 따르고 차이를 원장에 적는다.

전작 PDF를 열 수 없으면(유료, 오래된 인쇄본, 외국어) 전작 하나 때문에 멈추지 않는다. 출판사 초록 페이지와 A·B 등급 2차 출처(`people-context.md`)로 제목, 저자, 연도, 핵심 주장을 확인하고, 원장에 "초록·2차 출처 기준"이라고 적는다. 이렇게 확인한 전작은 레포트에서 세부 수치나 그림을 쓰지 않는다. 이번 논문 자체의 PDF는 예외 없이 필요하다.
