# 말투와 문장

집필 직전과 윤문 직전에 다시 읽는다. 무엇을 쓸지는 `planning.md`, 어떻게 쓸지는 이 문서다. 코드 블록은 결과물 예시라 음슴체로 적혀 있다.

## 0. 이야기꾼 원칙

이 스킬이 쓰는 글은 요약보다 이야기에 가깝다. 독자가 논문을 안 읽고도 "아 그래서 그렇구나" 하고 따라올 수 있어야 한다. 그러려면 설명의 모든 걸음이 페이지 위에 있어야 한다.

비약을 찾아서 채운다. 문장마다 처음 보는 독자 입장에서 "왜?", "그래서?", "그게 무슨 뜻인데?"를 묻는다. 앞 줄에서 바로 따라 나오지 않으면 비약이다.
- 결론만 있고 이유가 없으면: 원문이 댄 이유를 한두 줄로 풀어 넣는다.
- 용어가 결과를 대신하면: 그 용어가 실제로 무슨 일을 하는지 장면으로 보여준다.
- 숫자만 있으면: 무엇과 비교해서 큰지, 무슨 조건에서 잰 건지 붙인다.

나쁨 (비약):
```
레이블 스무딩으로 모델을 덜 확신하게 만듦
그랬더니 퍼플렉서티는 나빠지는데
정확도는 오히려 오름
```
왜 퍼플렉서티가 나빠지는지, 왜 그게 반전인지 페이지에 없다.

좋음:
```
보통 학습은 정답 단어에 확률을 몰아주도록 시킴
근데 이 논문은 정답에 너무 확신하지 말라고 일부러 가르침

그러니 정답 단어에 몰아주는 확률이 줄어들고
그 확률로 매기는 퍼플렉서티 점수는 나빠짐
근데 실제 번역 정확도는 오히려 오름
덜 확신하게 배운 모델이 번역은 더 잘한 거임
```

괄호로 설명을 때우지 않는다. "퍼플렉서티(모델이 헷갈리는 정도)"처럼 괄호에 설명을 밀어 넣으면 이야기가 끊기고 이해도 얕아진다. 설명이 필요하면 문장 흐름 안에서 푼다. 괄호는 용어의 원어나 공식 이름을 붙일 때만 쓴다 ("셀프 어텐션(self-attention)", "(잔차 연결, 레이어 정규화)").

라벨은 밑밥이 있을 때만 쓴다. "킬포는", "반전", "재밌는 건" 같은 말은 독자가 이미 비교할 앞쪽 사실을 알고 있을 때만 통한다. 없으면 라벨을 떼고 밑밥부터 깐다.

나쁨:
```
킬포는 감사의 글임
ByteNet 제1저자한테 영감 줘서 고맙다고 적어둠
```
ByteNet이 누구인지, 왜 웃긴지 모른다.

좋음:
```
앞에서 나온 ByteNet 기억남?
이 논문 결과 표에선 트랜스포머한테 진 비교 대상임

근데 감사의 글에 그 ByteNet 제1저자 이름이 있음
영감을 줘서 고맙다고 함
표에선 트랜스포머가 이긴 상대인데
감사의 글에선 영감을 받았다고 인사한 거임
```

### 직관 먼저, 이름은 나중

무엇이 일어나는지 장면으로 먼저 보여준다. 이름(용어)은 그다음에 붙이고 숫자로 확인하는 건 마지막이다. "셀프 어텐션은 ~이다"로 시작하지 말고 "모든 단어가 다른 모든 단어를 동시에 쳐다봄 / 이게 셀프 어텐션임"으로 쓴다.

앞에서 본 것에 기대어 설명한다. 새 개념은 독자가 이미 본 그림, 예시, 비유에 연결한다 ("앞의 its 그림에서 선 색이 두 개였던 거 기억남? / 그게 서로 다른 헤드였음"). 새 예시를 계속 꺼내는 것보다 하나를 여러 번 쓰면 더 깊이 이해된다.

## 1. 한 줄 = 한 호흡

문장이 아니라 호흡 단위로 줄을 바꾼다. 한 줄은 보통 8~25자, 길어도 40자 안쪽이다. 문장 하나를 2~4줄로 쪼개는 게 정상이다.

나쁨:
```
연구진은 초고속 카메라와 두 개의 마이크를 동기화하여 균열이 가장자리에 도달할 때만 소리가 발생한다는 사실을 확인하였다.
```

좋음:
```
초고속 카메라 1대에
마이크 2개를 달아서
전부 동기화시킴

그랬더니 예상 밖의 결과가 나옴

균열이 지나가는 동안엔
아무 소리도 안 남
```

- 줄을 끊는 자리: 시간·조건 부사 뒤("그러다", "2019년"), 긴 주어 뒤, 반전 직전.
- 반전 문장은 짧게 단독 줄로 둔다.
- 빈 줄은 장면 전환이다. 3~6줄마다 넣고, 12줄 넘게 빈 줄이 없으면 안 된다.

## 2. 종결 어미

음슴체가 기본이다. 명사형 종결과 명사 종결을 섞는다.

| 종결 | 쓰임 | 예 |
|---|---|---|
| ~임 | 사실, 정의 | "이게 핵심임" |
| ~음 / ~있음 / ~없음 | 존재, 상태 | "근데 한계가 있음" |
| ~함 / ~됨 | 행동, 결과 | "X선이 나옴" |
| ~라고 함 | 논문·타인의 주장 전달 | "초음파 영역이 대부분이었다고 함" |
| ~는 거임 | 설명 마무리 | "에너지가 폭발한다는 거임" |
| ~아님? / ~냐 | 독자 대신 던지는 가설, 질문 | "그럼 이거 그냥 마찰 아님?" |
| 명사 종결 | 짧은 펀치 | "찾음.", "진짜임." |

- 같은 어미가 5줄 이상 이어지지 않게 섞는다.
- 논문의 주장이나 추정은 "~라고 함"으로 전달한다.
- 쓰지 않는 어미: 존댓말(~습니다, ~해요), 평서체(~했다, ~이다. 직접 인용 안은 허용), 반말 대화체 남발(~거든, ~잖아는 한 레포트에 1~2번까지).

## 3. 강조와 구어

비속어 대신 쓴다.

| 느낌 | 대체어 |
|---|---|
| 엄청 빠르게 | 엄청 빨리, 미친 듯이 빨리, 순식간에 |
| 아주 자세히 | 현미경 수준으로, 프레임 단위로, 아예 뜯어서 |
| 이상함 | 진짜 이상함, 뭔가 이상함, 말이 안 됨 |
| 대단함 | 대박임, 역대급임 (숫자로 뒷받침될 때만) |

허용 구어: 진짜, 엄청, 완전, 아예, 그냥, 대놓고, 무려, 사실상, 떡하니, 들고 옴, 박아버림, 갈아엎음, 찍음, 털어봄, 뜯어봄, 기억해두셈, 보셈.

전환어: "근데 문제는", "그러다", "그럼 ~냐 하면", "사실 ~", "그 전에", "이제 본론임", "여기부터". "킬포는", "여기서 반전 하나" 같은 라벨은 비교할 앞쪽 사실이 바로 앞에 나왔을 때만 쓴다 (0절).

- "~해버림"은 파격적인 행동에만 쓴다.
- ㅋㅋ는 한 레포트에 0~2번, 느낌표는 거의 쓰지 않는다. 담담하게 이상한 걸 말할 때 더 재밌다.
- 이모지와 줄표(—)는 쓰지 않는다.
- 금지: 비속어·욕설(초성 포함), 혐오·비하·집단 일반화, 저자나 기관 조롱.

## 4. 사람이 쓴 글

커뮤니티 말투는 겉옷이다. 어미를 음슴체로 바꿔도 AI가 쓴 글은 티가 난다. 사람이 쓴 정보글은 고르지 않다. 어떤 파트는 길고 어떤 파트는 두 줄로 끝난다. 문장 모양도 매번 다르고 강조는 정말 이상한 곳 한두 군데에만 한다. 아래 패턴이 보이면 고친다.

형용사로 대단함을 주장하지 않는다. 이전 대비 무엇이 얼마나 바뀌었는지로 보여준다.

### 격식체 번역투

| AI 문체 | 고친 예 |
|---|---|
| 본 논문은 ~를 제안합니다 | 이번에 들고 온 건 ~임 |
| 흥미롭게도, 주목할 만한 점은 | (삭제하고 사실만) / 근데 여기서 이상한 게 |
| 혁신적인, 획기적인, 게임 체인저 | (삭제. 뭐가 얼마나 달라졌는지 숫자로) |
| ~라고 할 수 있습니다 | ~임 / ~라고 봄 |
| 다양한 분야에 활용될 것으로 기대됩니다 | (논문이 말한 응용만 "~에 쓸 수 있다고 함") |

### 음슴체로 바꿔도 남는 AI 티

| 패턴 | 예 | 고치는 법 |
|---|---|---|
| 틀로 찍은 나열 | "①은 ~하고 / ②는 ~하고 / ③은 ~하고 / ④는 ~하자는 거임", "정하고 / 나누고 / 추적하고 / 막는" | 같은 모양 줄이 세 줄 이상 이어지면 틀이다. 제일 중요한 하나만 말하거나 한 문장으로 묶는다 |
| 정리 멘트 | "돌아보면", "정리하면", "한마디로", "결국 ~인 셈", "~하자는 얘기였음" | 지운다. 되짚을 게 있으면 앞에서 쓴 장면 하나를 다시 꺼낸다 |
| 예고 멘트 | "알고 보면 더 볼 맛이 남", "여기부터가 진짜임", "이게 핵심임", "딱 이거임" | 예고하지 말고 그 사실을 바로 꺼낸다 |
| 입장 요약 반복 | "이 논문 답은 아니라는 쪽임"을 도입과 결론에 똑같이 | 같은 판정 문장을 두 번 쓰지 않는다. 두 번째는 근거가 쌓인 만큼 구체적으로 |
| 판정 어미 도배 | "~라고 봄", "~라고 함"이 한 파트에 서너 번 | 파트 첫머리에 "논문은"을 한 번 걸면 나머지는 평서로 쓴다 |
| 접속어로 여는 줄 반복 | 줄마다 "그래서", "근데", "그럼"으로 시작 | 앞 파트의 장면이나 명사를 받아서 시작하거나, 그냥 사실로 시작한다 |
| 공식 마무리 | 매 글 끝 "~가 관전 포인트임", "앞으로가 기대되는 대목임" | 다음에 실제로 일어날 일(날짜, 누가 무엇을)을 말하거나, 사실 한 줄로 끝낸다. 전망 말투는 근거가 있을 때 한 번만 |
| 고른 리듬 | 모든 문단이 세 줄, 모든 파트가 같은 길이 | 짧게 끝날 파트는 짧게 둔다 |

나쁨 (이 스킬이 실제로 쓴 마무리):
```
돌아보면 막히는 곳 네 개에 처방이 하나씩 붙음
①은 실험을 서비스로 만들어 줄이고
②는 조건 해시와 담보로 실패를 돌리고
③은 AI 예측시장과 사후 보상으로 값을 매기고
④는 재현 에스크로와 추첨으로 믿게 만들자는 거임
...
이 두 칸을 누가 먼저 채우느냐가
이 설계도가 실제 시장이 될지의 관전 포인트임
```
정리 멘트, 네 줄짜리 틀, 공식 마무리가 다 들어 있다.

좋음:
```
Penadés 팀 얘기로 돌아가면
가설은 이틀이면 나오는데 증명엔 10년 가까이 걸렸음
이 논문은 그 10년짜리 줄을 누가 먼저 서느냐를
시장으로 정하자는 제안서임

근데 그 시장에 꼭 필요한 두 개는
저자들도 아직 없다고 적어둠
아이디어의 값을 나중에 재는 법,
복제되는 에이전트에게 신원을 주는 법
```

### 한국어 AI 문체 규칙에서 가져온 것

[im-not-ai](https://github.com/epoko77-ai/im-not-ai)(MIT)의 한국어 AI 티 목록 가운데 음슴체 해설에도 그대로 나타나는 것이다. 괄호 안은 그 레포의 규칙 번호다.

| 패턴 | 예 | 고치는 법 |
|---|---|---|
| 대구 반복 (C-8) | "A가 아니라 B" "~는 아님"이 연달아 | 한 번만 살리고 나머지는 한쪽만 말하는 평서로 |
| 설명형 종결 과다 (I-3) | "~한다는 거임", "~라는 뜻임"이 계속 | 한 레포트에 서너 번까지. 나머지는 "~임", "~함"으로 바로 끝낸다 |
| 분열문 (D-8) | "핵심은 ~임", "문제는 ~라는 점임" | 주어와 서술을 바로 잇는다. "문제는"을 전환어로 한두 번 쓰는 건 괜찮다 |
| 도치 결산 (D-10) | "~한 이유임" | "그래서 ~임" 순서로 |
| 범위 상승 (A-21) | "단순한 X를 넘어 Y" | "X만이 아니라 Y"로 풀거나 넘어-구를 지운다 |
| 사전 은유 (D-14) | 잠식, 청사진, 적신호, 신호탄, 뿌리내리다 | 명제로 푼다 ("잠식함" → "점유율을 뺏음") |
| 연결어미 뒤 쉼표 (C-11) | "읽고, 쓰고," | 쉼표를 뺀다. 음슴체는 줄바꿈이 쉼표 역할을 한다 |
| 같은 유보 어미 반복 (A-10, G-1) | "~할 수 있음", "~라고 봄"이 줄줄이 | 유보는 남기고 형태만 바꾼다 ("~할 수도 있음", "~일지 모름"). 단정으로 올리지 않는다 |
| 결산 접속어 (D-1, D-9) | "따라서", "결국", "즉"이 거듭 | "결국"은 한 번만. 인과가 자명하면 지운다 |

고칠 때 지킬 것도 같은 레포에서 가져왔다.
- 서법 보존: 원문이 "~일 수 있다"면 고친 뒤에도 유보가 남아야 한다. AI 티를 뺀다고 유보를 단정으로 올리지 않는다.
- 빼기 전용: 걷어내기만 한다. 고치면서 새 비유나 상투구를 심지 않는다.
- 국소 수정: 걸린 줄만 고친다. 글 전체를 새로 쓰면 사실이 흔들린다.

## 5. 쉽게 말하면, 정확히는

핵심 개념마다 짝으로 쓴다.

```
쉽게 말하면
문장을 통째로 외운 다음에 번역하는 거임

정확히는
입력 문장 전체를 고정 크기 벡터 하나로 압축하고
그 벡터에서 번역문을 풀어냄
```

- "쉽게 말하면"은 일상어나 비유다. 틀린 이해를 만들면 안 된다.
- "정확히는"은 원문 용어와 조건을 그대로 쓴다. 원장 태그는 여기에 단다.
- 추상 개념을 말했으면 바로 다음에 논문 속 예시를 보여준다. 그림 앞에는 "뭘 봐야 하는지" 한 줄을 쓴다 ("its에서 선이 어디로 뻗는지 보셈").

## 6. 재미는 보여준다

"웃김", "재밌음"으로 선언하지 않는다. 웃음은 기대와 결과의 격차에서 나온다. 기대 쪽을 먼저 보여주고 결과를 나란히 놓은 뒤, 펀치 한 줄로 닫는다.

| 재료 | 밋밋한 버전 | 펀치 버전 (틀) |
|---|---|---|
| 규모의 격차 (틀) | "이 연구로 벌어진 일이 좀 웃김 / [결과 숫자]" | "당시 목표는 [원래 목표] / [원래 규모]로 해냄 / 지금은 [결과 숫자] / [원래 목표]로 나온 게 [지금의 위치]가 된 거임" |
| 규모의 격차 (예) | "이 논문으로 벌어진 일이 좀 웃김 / 피인용 19만 회" | "자랑한 건 번역 점수 2점, GPU 8장 서버 한 대 / 지금은 피인용 19만 회, 저자 7명이 창업 / 2점 올렸다고 자랑하던 부품이 GPT의 T가 된 거임" |
| 규칙의 반전 | "저자 순서는 무작위라고 적혀 있음" | "다들 'Vaswani et al.'로 인용하는데 / 그 1번 자리도 무작위로 정해진 거임" |
| 경쟁자에게 감사 | "킬포는 감사의 글임 / 경쟁 번역기 제1저자한테 영감 줘서 고맙다고 적어둠" (왜 웃긴지 모름) | "앞에서 나온 ByteNet 기억남? / 결과 표에선 트랜스포머한테 진 비교 대상임 / 근데 감사의 글에 그 제1저자 이름이 있음 / 표에선 트랜스포머가 이긴 상대인데 감사의 글에선 영감을 받았다고 인사한 거임" |
| 직관과 반대인 결과 | "여기서 반전 하나 / 일부러 덜 확신하게 만들었더니 점수가 오름" (무엇이 반전인지 모름) | "보통 학습은 정답에 확률을 몰아주게 시킴 / 근데 일부러 덜 확신하게 가르침 / 그랬더니 번역은 오히려 더 잘함" |
| 적정값 | "헤드 수를 바꿔봄" | "헤드 1개면 떨어지고 / 그럼 많을수록 좋냐 하면 32개도 떨어짐 / 적당히가 최고였음" |

- 펀치는 사실을 비틀지 않는다. 원장 범위 안에서 배치와 순서로만 웃긴다.
- 기대 쪽을 과장하거나 깎아서 격차를 키우지 않는다. "소박한 계획이었음"처럼 원문보다 약하게 옮기지 않는다.

## 7. 정확성과 말투

말투가 가벼워도 논문의 확신 수준은 그대로 옮긴다.

| 원문 | 옮김 |
|---|---|
| we prove | 증명함 |
| consistent with | ~와 맞아떨어진다고 함 (증명함 아님) |
| significance of Nσ / p < 0.05 | N시그마 수준으로 유의하다고 함 / 우연일 확률이 5% 미만이라고 함 |
| false alarm rate | 잡음이 이런 신호를 흉내 낼 빈도가 [값]이라고 함 |
| 90% credible interval | [범위] 사이일 가능성이 90%라고 봄 |
| 95% confidence interval | 95% 신뢰구간이 [범위]라고 함 |
| upper limit | 많아도 [값] 이하라고 함 |
| correlated / associated with | 같이 움직인다고 함 (원인이라고 안 함) |
| demonstrated in vitro / in cells / in vivo | 시험관 안에서 / 세포에서 / 생체에서 보였다고 함 (단계를 건너뛰지 않음) |
| preprint | 아직 동료 평가 전인 프리프린트임 |
| we show / demonstrate | 보여줌, 확인함 |
| suggest / indicate | ~로 보인다고 함 |
| we suspect / hypothesize | ~라고 추정함, "그럴 거라고 본다"고 씀 |
| apparently / appear to | ~하는 것 같다고 함 |
| clearly | 확실히 ~했다고 씀 |
| may / might / could | ~일 수도 있다고 함 |
| in mice / in vitro / on benchmark X | 쥐 실험에서 / 세포 수준에서 / X 벤치마크에서 (조건 생략 금지) |
| state-of-the-art | (당시) X에서 최고 기록 + 날짜 |

제목 동사도 증거 강도에 맞춘다. "규명됨/증명됨"은 원문이 그렇게 말할 때만, "밝혀냄/확인함"은 실험으로 보였을 때, 그 외에는 "나옴/발표됨"이 기본이다.

### 비유
- 비유보다 실제 사례가 먼저다. 원장에 논문 자신의 예시나 실제 일화가 있으면 그걸 쓴다. 예: "아이디어는 공짜, 검증은 비쌈"을 식당 주방으로 빗대지 말고 "사람 팀이 10년 걸려 증명하려던 가설을 AI는 이틀 만에 1순위로 냄", "결정 구조는 수백만 개 예측하지만 확인은 하나씩 합성"처럼 원장에 있는 사례로 보여준다.
- 한 레포트에 1~2개, "비유하면"을 붙인다.
- 쓰기 전에 대응표를 머릿속으로 채운다. 원래 현상의 부품(무엇이 늘고, 무엇이 모자라고, 누가 고르고, 누가 비용을 내나) 하나하나가 비유 속 무엇에 대응하는지. 논문 논지가 걸린 축에서 하나라도 어긋나면 버린다. 예: 식당 주문은 들어온 순서대로 다 요리하는 구조라, "수많은 가설 중 무엇을 골라 실험실 시간을 배정하나"가 논점인 글에선 축이 어긋난다.
- 한 줄로 직접 말할 수 있는 메커니즘은 비유하지 않는다. "전자서명은 깨지는 도장"보다 "서명이 붙은 데이터는 한 글자만 바뀌어도 서명 확인이 실패함"이 짧고 정확하다.
- 원래 현상의 원인 구조를 보존해야 한다. RNN의 병목은 앞 결과가 있어야 다음을 계산하는 의존성이라 "이어달리기"는 맞고, "은행 창구 대기줄"은 자원만 늘리면 풀리는 문제처럼 보여 틀린 이해를 만든다.
- 개념에 은유 이름("청구서", "폭탄")을 붙여 글 내내 반복하지 않는다. 반복되는 라벨은 원문 용어나 담백한 말("대가", "비용")로 쓴다.

## 8. 용어

- 첫 등장은 `확산 모델(diffusion model)`처럼 병기하고 이후 한 가지로 통일한다.
- 번역이 어색하면 영어 그대로 쓰되 첫 등장 때 한 줄로 설명한다.
- 약어는 첫 등장 때 푼다.

## 9. 소제목과 제목

파트 안에는 소제목을 쓰지 않는다. 커뮤니티 정보글은 소제목 없이 줄바꿈과 여백만으로 넘어간다. 파트마다 "A는 ~, B는 이거" 같은 소제목을 붙이면 AI가 쓴 글처럼 보인다. 파트의 역할은 첫 줄이 한다 (`planning.md` 7절).

AI 티가 나는 제목·문장 패턴 (글 제목에도, 본문에도 쓰지 않는다):
- "A는 ~, B는 이거" 식의 대구
- "키워드: 설명" 식의 콜론 제목 ("결과: 번역 기록을 갈아치움")
- "~의 비밀", "~의 진짜 이유", "~의 모든 것", "알아보자", "파헤쳐 봄"
- "숨은 백미", "게임 체인저" 같은 평가 명사

글 전체의 제목은 하나만 둔다. 커뮤니티 베스트 제목 패턴을 쓰되 과장하지 않는다.
- `[독자가 아는 것]의 [무엇]은 원래 [뜻밖의 것]이었음`
- `[N]년 동안 풀리지 않던 [문제]가 풀림` (원문 근거가 있을 때만)
- `[대상]이 어떻게 [결과]를 해냈는지 알아봄`
- `현재 [분야]에서 난리 난 [대상]` ("난리"의 근거가 원장에 있을 때만)

## 10. 윤문 체크리스트

파트마다 소리 내 읽듯이 확인한다. 전체 평가는 `rubric.md`로 한다.

- [ ] 한 줄에 한 호흡인가. 40자 넘는 줄이 없나.
- [ ] 음슴체로 통일됐고 같은 어미가 5줄 이상 이어지지 않나.
- [ ] 파트 안에 소제목이 없나. 첫 줄이 앞 파트를 받아서 시작하나.
- [ ] 처음 보는 독자가 "왜?"라고 물을 곳마다 답이 페이지에 있나. 괄호로 설명을 때운 곳이 없나.
- [ ] "킬포", "반전" 같은 라벨 앞에 비교할 앞쪽 사실이 나왔나.
- [ ] 3줄 요약의 첫 줄이 도입 질문에 답하나. 세 줄 모두 주어가 분명하고 본문보다 단순화되지 않았나 (`planning.md` 5-1절).
- [ ] 형용사 대신 숫자와 비교 대상으로 말했나.
- [ ] 논문의 주장·추정에 단정형을 쓰지 않았고, 조건이 빠진 문장이 없나.
- [ ] 개념마다 "쉽게 말하면"과 "정확히는"이 있고, 그림 앞에 볼 곳이 적혀 있나.
- [ ] "웃김", "재밌음" 선언이나 억지 은유 라벨이 없나.
- [ ] 소리 내 읽었을 때 사람이 쓴 글 같나. 틀로 찍은 나열, 정리 멘트, 예고 멘트, 공식 마무리가 없나 (4절).
