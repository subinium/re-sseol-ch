# 평가 기준

집필 후, 빌드 전에 채점한다. 정확성은 3점이어야 하고, 나머지 여섯 항목은 2점 이상이어야 빌드한다. 기준에 못 미치면 고치고 다시 채점한다. 최종 보고에 점수와 고친 것을 적는다.

| 항목 | 3점 | 2점 | 1점 (고칠 것) |
|---|---|---|---|
| 정확성 | 검사 ERROR 0, 사실마다 원장 태그, 독립 팩트체크(또는 파트별 원장 재대조)를 마치고 지적을 원문으로 확인해 반영함 | 팩트체크를 아직 안 함 | 태그 없는 사실, 원문보다 센 표현, 조건 누락이 남음 |
| 연계성 | 내용 파트의 80% 이상이 척추 마디나 밑밥·회수에 연결되고, 밑밥이 전부 회수되고, 검사의 "연결 약함" 경고가 없고, 흐름 검토에서 "끊김"이 없고, 도입 질문에 더 정확히 답한 뒤 맺음 파트가 지금으로 연결하고 앞을 가리키며 3줄 요약으로 닫힘 | 연결 60~80%, 회수 안 된 밑밥이 하나, 흐름 검토에서 "약함"이 둘 이상, 마무리가 도입 질문을 다시 부르지 않음, 또는 지금·앞으로 없이 회수 한 줄로 끝남 | 연결 60% 미만, 논문 목차 순서 나열, 도입 질문에 바로 답함, 근황이나 출처로 끝남 |
| 재미 | 이 논문에 있는 재미 재료(격차, 숨은 디테일, 타이밍, 엇갈린 주장, 인물 교차 중 해당하는 것) 3개 이상이 밑밥 뒤 펀치로 배치됨 | 재료 1~2개, 또는 일부가 목록으로 끝남 | "웃김", "재밌음"으로 선언만 함, 재료가 목록으로만 나열됨 |
| 설명력 | 처음 보는 독자가 "왜?"라고 물을 곳마다 답이 페이지에 있음. 새 개념이 장면 → 이름 → 숫자 순으로 나오고, 앞에서 본 예시에 기대어 설명됨. 흐름 검토에서 비약 지적이 없음 | 비약 지적이 1~2곳, 괄호로 때운 설명이 남음, 또는 3줄 요약이 본문보다 단순화됐거나 주어가 흐림 | 결론만 있고 이유가 없는 문장이 여럿, 용어가 설명을 대신함, 밑밥 없는 라벨 |
| 전문성 | 유형별 전문성 재료를 채우고(해당 없음은 이유 적음) 결정적 증거와 설계 이유를 다룸. "쉽게 말하면/정확히는" 짝이 핵심 개념마다 있음 | 재료는 있으나 결정적 증거나 설계 이유가 빠짐 | 결과 숫자나 수식 한 장뿐 |
| 사회 맥락 | 친숙도에 맞는 도입, 지금의 위치가 날짜 박힌 사실 2개 이상으로 들어감 | 친숙도는 맞으나 지금의 위치가 1개 이하 | 유명한 대상을 "~란 게 있음"으로 소개, 날짜 없는 현재형 |
| 말투 | 검사 WARN을 모두 검토함, 어미 리듬이 살아 있음, 소제목·억지 은유 라벨·AI 티 나는 제목 패턴 없음, 틀로 찍은 나열·정리 멘트·공식 마무리 없이 사람이 쓴 글로 읽힘 | 검사는 통과하나 단조로운 구간이 있음 | 존댓말·평서체 혼용, 긴 줄, AI 문체 |

채점할 때 `outline.md`의 파트 목록 "연결" 칸을 세서 연계성 비율을 계산한다. 이어서 아래 질문에 답한다.
- 재밌다고 생각한 줄마다, 그 앞에 기대 쪽이 나왔나
- 전문가가 읽었을 때 "틀렸다" 또는 "빠졌다"고 할 곳이 있나
- 이 분야를 처음 보는 사람이 "쉽게 말하면" 줄만 읽어도 흐름을 따라올 수 있나

## 흐름·설명 검토 지시문

검사 스크립트는 표면 패턴만 본다. 흐름과 비약은 처음 읽는 독자 입장에서 따로 검토한다. 서브에이전트에게 `report.md`만 주고(원장·원문은 주지 않음) 아래를 시킨다. 서브에이전트를 쓸 수 없으면 직접 파트 경계마다 같은 질문에 답한다.

```
너는 이 분야를 처음 보는 독자다. report.md를 처음부터 한 번에 읽는다. 파일은 수정하지 않는다.
파트(`---`로 구분) 경계마다 판정한다.
- 좋음: 앞 파트 끝을 읽고 나면 다음 파트가 왜 나오는지 알 수 있음
- 약함: 이어지긴 하지만 한 박자 늦게 이해됨
- 끊김: 왜 이 얘기로 넘어왔는지 모르겠음, 또는 앞 파트가 예고한 것과 다른 얘기가 나옴
추가로 찾는다.
- 앞에서 예고하거나 "기억해두셈"이라고 했는데 회수되지 않은 것
- 처음 나오는데 설명 없이 쓰인 용어나 이름
- 마지막 파트가 처음 질문으로 돌아와 답하고, 지금과 앞으로를 보여주며 닫히는지
- 비약: "왜?"라고 묻게 되는데 답이 페이지에 없는 문장
- 괄호 안에 밀어 넣은 설명 (용어의 원어나 공식 이름은 제외)
- "킬포", "반전" 같은 라벨인데 무엇과 대비되는지 앞에 안 나온 것
- 사람이 안 쓸 것 같은 줄: 같은 모양으로 찍어낸 나열, "돌아보면" 같은 정리 멘트, "볼 맛이 남" 같은 예고, 매번 같은 전망 문구
출력: 경계 번호 | 판정 | 이유 | 고칠 방향 (한 줄씩). 좋음은 번호만 나열. 이어서 비약·괄호 설명·라벨·AI 티 문제를 파트 번호 | 문장 | 무엇이 문제인가 로 나열.
```

## AI 티 검토 지시문

집필과 흐름 검토를 마친 원고에 쓴다. 서브에이전트에게 `report.md`와 `style-guide.md` 4절을 주고 아래를 시킨다. 서브에이전트를 쓸 수 없으면 같은 기준으로 직접 읽는다.

```
너는 한국어 AI 문체 검토자다. 파일은 수정하지 않는다.
이 글은 일부러 한국 커뮤니티 정보글 말투(음슴체, 한 줄 한 호흡, 짧은 줄바꿈)로 쓴 논문 해설이다.
음슴체, 줄바꿈, "근데"·"진짜"·"~임" 같은 구어는 의도된 장르라 지적하지 않는다.
그 아래 남은 AI 티를 찾는다: 번역투, 틀로 찍은 나열, 대구 반복, 분열문("핵심은", "해법은 X임"),
결산·예고 멘트, 공식 마무리, 설명형 종결("~는 거임") 과다, 같은 판정 어미 반복,
파트 경계마다 같은 모양으로 여는 문장, 사전 은유, 사람이면 안 쓸 것 같은 매끈한 문장.
지킬 것:
- 원문이 유보("~할 수 있다고 봄")면 수정안도 유보를 유지한다.
- 새 비유나 상투구를 넣는 수정안을 내지 않는다.
- 숫자, 날짜, 고유명사, 인용은 바꾸지 않는다.
- 자연스러운 커뮤니티 문장은 건드리지 않는다. 가장 심한 것부터 20곳 이내.
출력: 파트 번호 | 원문 줄 | 패턴 | 수정안(음슴체 유지, 줄바꿈은 / 로). 마지막에 전체 인상 3줄 이내.
```

지적은 원문과 대조한 뒤 반영한다. 밑밥과 회수("기억해두셈"과 그 회수)처럼 이 스킬이 일부러 쓰는 장치는 예고 멘트와 구분해서 남긴다.
