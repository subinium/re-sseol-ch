# 팩트 원장과 검증

쓰기 전에 원장을 만들고, 쓴 뒤에 원장으로 대조한다.

## ledger.md 형식

```markdown
# 팩트 원장: <논문 제목>
기준일: YYYY-MM-DD
원문 버전: arXiv <ID>v<N> 또는 게재본
날짜 기준: arXiv 최초 공개 / 저널 온라인 게재 / 인쇄 (arXiv가 없으면 저널 온라인 게재일)

## F: 논문 본문
- F1 | 초록 | "We propose ..." | 핵심 주장 요지
- F2 | p.N, Table 2 | "<원문 수치 문장>" | 조건을 포함한 한국어 요지

## L: 계보와 관계
- L1 | arXiv:<ID> p.1 | 저자, 소속, 공개일, 인용 문맥 문장 | 관계: 확장

## P: 사람과 기관
- P1 | 논문 p.1 저자란 | "<원문 소속 표기>" | 요지

## W: 외부 출처
- W1 | <URL> (YYYY-MM-DD) | "<인용>" | 요지
```

규칙:
- 한 줄에 한 사실. 인용은 원문 그대로 쓴다.
- 위치는 최대한 좁게 적는다 (페이지, 표·그림 번호, 절 번호, URL).
- 네 번째 칸은 레포트에서 쓸 한국어 요지다. 여기서 이미 과장이 생기지 않게 원문 확신 수준을 유지한다.
- 숫자는 원문 표기 그대로. 반올림, 단위 환산, 만·억 표기로 바꾼 값은 계산식을 같이 적는다. 예:
  - `12.1 vs 4.0 | 약 3배 (12.1/4.0=3.03)`
  - `"410 Mpc" | 약 13억 광년 (410 × 326만 광년/Mpc ≈ 13.4억)`
  - `"36 +5 −4" | 36 (위로 5, 아래로 4 범위)` (위첨자 ±는 PDF 텍스트에서 깨지기 쉬우니 표 이미지로 확인)
- 변하는 값(인용 수, 소속)은 조회 날짜를 적는다.

## 레포트 태깅

사실 주장이 끝나는 줄 끝에 `<!-- F2 -->`를 단다. 여러 개면 `<!-- F2 L3 -->`. 빌드할 때 지워진다. 사실이 없는 연결 줄에는 달지 않는다.

| WARN | 평서체, 40자 넘는 줄, AI 문체, 이모지, 줄표, '개-' 강조, ㅋㅋ 3회 이상, 느낌표 4회 이상, 같은 어미 5줄 연속, 빈 줄 없이 12줄 초과, 태그 없는 파트, 파트 길이(6~22줄)·개수(10~26), 그림 8장 미만, 그림 있는 내용 파트 60% 미만, 척추 마디가 4개 파트 미만, `outline.md` 없음, 자동 감지 커뮤니티 요소 3개 미만, 그림 캡처·사용 허락 언급, "웃김"·"재밌음" 같은 재미 선언, 파트 안 소제목, 괄호로 때운 설명, "킬포" 라벨(밑밥 확인용), 3줄 요약이 맨 위에만 있음, 3줄 요약 첫 줄이 제목과 안 이어짐, "~한 게 X임" 구문, 파트 경계 연결 약함(첫 줄에 연결어·번호·지시어가 없고 앞 파트 끝과 겹치는 핵심어도 없음), 번호로 찍어낸 나열, '~고'로 이어 붙인 나열, 정리·예고 멘트, 전망 문구 반복, 같은 문장 반복, 파트당 '~라고 봄/함' 과다, 접속어로 여는 줄 비율, 대구 반복, '~는 거임' 과다, 분열문, 사전 은유 |

자동 감지하는 요소는 "3줄 요약", "쉽게 말하면 … 정확히는" 짝, "내용 추가하면", 척추 마디, 이렇게 네 가지다. 척추 마디는 `outline.md`의 "- 마디: <이름> |" 줄에서 이름을 읽어 몇 파트에 나오는지 센다 (`outline.md`가 없으면 ①② 기호를 센다). 숨은 디테일, 타이밍, 엇갈린 주장, 밑밥과 회수는 자동으로 못 잡으므로 채점(`rubric.md`) 때 직접 확인한다.

숫자 검사는 원문·원장·계보에 같은 숫자가 있는지만 본다 ("17"은 "2017" 안에서 찾지 않는다). 파생값은 원장에 계산식을 적어두면 통과한다.

## 독립 팩트체크 지시문

검사 통과 뒤 서브에이전트에게 아래를 준다.

```
너는 논문 해설 레포트의 팩트체커다. 파일은 수정하지 말고 보고만 한다.
입력: report.md, ledger.md, text.txt(원 논문, 페이지 표시 포함), lineage.md,
전작·후속작 원문 폴더, figures/, 정리 이미지 스펙(JSON).
파트마다 찾아라.
1. 원문과 다른 숫자·날짜, 빠진 조건(데이터셋, 모델 크기, 비교 대상)
2. 원문 확신 수준보다 강한 표현 (suggest를 "증명함"으로 쓴 경우 등)
3. 원장 ID가 그 문장을 실제로 뒷받침하지 않는 경우
4. 계보·인과 서술 중 원문 근거가 없는 것. "처음", "그 사람임", "가져감", "~ 덕분에", "~라서 고름" 같은 연결은 전작·후속작 원문으로 확인. 전작의 성과를 원문보다 깎아 쓰지 않았는지도 확인
5. 쉬운 설명이나 비유가 전문적으로 틀린 이해를 만드는 경우 (비유가 원래 현상의 원인 구조를 보존하는지)
6. 그림 설명이 그림 내용과 다른 경우 (그림 파일을 직접 열어 확인)
7. 원장 자체의 오류 (인용문이 원문에 없음, 페이지 틀림)
출력: 파트 번호 | 문제 문장 | 원문 근거(파일:페이지 인용) | 심각도(오류/과장/사소) | 수정안.
문제 없는 파트는 "파트 N 문제 없음 (확인 항목 수)". 원문으로 확인된 것만 쓴다.
```

지적은 원문으로 직접 확인한 뒤 고친다. 고친 내역은 최종 보고에 적는다.

## 자주 나오는 오류

- 원문 내부 불일치: 초록·표·본문의 숫자가 다를 수 있다. 셋을 교차 확인하고, 값이 다르면 다른 값을 모두 원장에 적는다.
- 비교 문장의 범위: "이 모델이 비용도 적음"이 특정 크기에만 맞는 경우가 있다. 모델 크기별로 나눠 확인한다.
- 조건의 범위: 원문의 조건이 무엇에 걸리는지 확인한다. 예: "n<d일 때 빠름"은 층당 계산량 얘기이고 병렬성과는 별개다.
- 전작의 주장 뒤집기: 이번 논문이나 다른 논문의 요약을 믿고 전작이 "~에 약했다"고 쓰면, 전작 본인은 반대로 주장했을 수 있다.
- "처음" 과장: 관련 연구 절을 읽으면 대개 더 이른 연구가 있다.
- 인과 과장: 저자 주장은 "~라고 함"으로 전달한다. 따로 떼어 검증한 실험이 없으면 "증거"라고 부르지 않는다.
- 후속 연구 이유 골라 쓰기: 후속 연구가 이유를 여러 개 댔으면 척추와 맞는 것만 쓰지 않는다.
- 전작 성과 축소: 서사를 살리다 보면 전작이 못 한 것처럼 쓰기 쉽다. 전작이 스스로 주장한 성과 문장을 확인한다.
- 적용 범위 누락: 학습과 생성(추론), 인코더와 디코더, 개발 세트와 테스트 세트처럼 조건이 갈리는 곳을 확인한다.
- 예시를 증거로 씀: 그림 하나는 예시다. 근거가 이론인지 실험인지 구분한다.
- 실험 조건 섞기: 한 변수를 바꾸면 다른 변수도 같이 바뀌는 실험(예: 계산량 고정으로 헤드 수와 헤드당 차원이 같이 바뀜)은 그 조건을 적는다.
- 공개일 순서: 같은 해 논문은 월·일까지 비교한다.
- 소속 시점: 전작 저자의 소속은 당시 소속으로 쓴다.
- 공동 저자 지위: 공저자 중 한 명을 "만든 사람"으로 쓰지 않는다. 저자 순서와 기여 각주를 확인한다.
- 인용 수 혼용: 출처마다 몇 배 다르다. 한 출처만 쓴다.
- arXiv 버전: 버전마다 숫자가 다를 수 있다. 원장 머리에 읽은 버전을 적는다.
